# 测试开发面试重点（测试基础+用例设计+自动化+性能安全）

## 测试基础
- 软件测试定义与目的：发现缺陷、验证需求、提供质量反馈，不只是"找Bug"。
- 测试流程：需求分析→测试计划→测试设计→测试执行→缺陷跟踪→测试报告→回归测试。
- 测试左移（Shift-Left）：需求/设计阶段就介入质量活动，早发现早修复，缺陷成本随阶段指数增长。
- 测试金字塔：单元测试（>90%自动化）→集成测试（60-80%）→系统/UI测试（20-40%），投资回报递减。
- 核心竞争力：业务理解 + 系统性用例设计 + 工程化自动化能力。

## 测试用例设计
- 等价类划分：将输入划分为有效/无效等价类，每类取代表性数据，减少冗余。
- 边界值分析：等价类边界的值最易出错，如范围[1,100]测试0/1/100/101。
- 判定表法：多条件组合场景（如会员×节假日×提前天数→价格），穷举条件与结果映射。
- 场景法：模拟用户操作流程（主流程+异常分支），通过流程图覆盖完整业务路径。
- 错误推测法：基于经验推测易错点（如文件上传：空文件/超大文件/病毒文件/格式不符）。
- 状态迁移法：测试有状态变化的对象（如订单状态、电梯状态），验证状态转换正确性。

## 测试类型
- 黑盒测试 vs 白盒测试：关注外部行为 vs 关注内部代码逻辑，互补使用。
- 单元测试：最小可测试单元（函数/类），Mock外部依赖，开发编写，CI自动执行。
- 集成测试：多模块/服务交互验证，关注接口契约、数据传递、依赖协同。
- 回归测试：修改后确认旧功能未被破坏，高度依赖自动化用例。

## 自动化测试
- ROI公式：(节省的手工测试时间 × 执行频率) - (脚本开发时间 + 维护成本)。
- Web自动化工具：Selenium（多语言/多浏览器、成熟但慢）、Cypress（开发者友好、JS-only）、Playwright（现代化、多语言、快）。
- API测试工具：Postman/Reqable/Insomnia，结合Newman/CI实现自动化回归。
- CI/CD集成：Jenkins/GitLab CI/GitHub Actions中自动触发，测试报告与失败告警。

## 性能测试
- 压测类型：负载测试（预期负载下验证）、压力测试（超负载找极限）、稳定性测试（长时间运行查泄漏）。
- 关键指标：TPS/QPS、响应时间（P50/P95/P99）、错误率、CPU/内存/磁盘IO/网络带宽。
- 瓶颈定位：数据库慢查询、连接池打满、线程池饱和、网络带宽、GC停顿。

## 安全测试
- OWASP Top 10：XSS/SQL注入/CSRF/身份认证失效/敏感信息泄露/访问控制失效等。
- SQL注入测试：`' OR '1'='1 --`、`' UNION SELECT --`，验证参数化查询。
- 越权测试：水平越权（访问同角色他人数据）、垂直越权（普通用户访问管理接口）。
